# v0.1.0 pilot checklist

Target: `organizer.nunezserver.online`. There is no staging vhost. Automated tests use local XAMPP MariaDB; the live pilot and host checks below remain **pending** until the owner explicitly authorizes VPS changes, Telegram bot setup and production test accounts. Never use real credentials or chat IDs in this document or GitHub.

Record date, operator, release commit, backup set identifier, and pass/fail evidence in a private operations record. Keep this public checklist free of personal data. A checked automated test is evidence for its specific behavior, not a substitute for the live scenario.

## Gates before live testing

- [ ] Read-only VPS audit reviewed: dedicated app Unix user and MariaDB schema, PHP 8.4, OpenLiteSpeed vhost, TLS, cron, queue worker and SMTP. See [runbook](../runbook.md).
- [ ] Owner approves production deployment, bot configuration and two invited pilot users. Confirm `organizer.nunezserver.online` DNS and HTTPS.
- [ ] Install from a reviewed `master` commit. Verify `/healthz`, `/readyz`, `nunez:health`, queue worker, scheduler, email verification and password reset. Confirm no WordPress file access or DB grants.
- [ ] Verify HTTPS redirect, HSTS, CSP, frame denial, secure cookies and protected `.env` on the live host. Complete [security checklist](../security/threat-model.md).
- [ ] Make an encrypted backup; verify checksums and decryptability; restore to the **separate scratch database** using the runbook. Compare schema and representative table counts, then remove scratch data. Never restore over production for a drill.
- [ ] Confirm rollback target and operator contact before creating pilot data.

## Pilot sequence and fault record

1. Invite and verify Alice and Bob. Pair each with a separate real private Telegram account.
2. Create one short block per user ending at nearly the same time. Confirm distinct prompts. Alice answers Yes; Bob answers No. Check task pages and response history.
3. At Bob's next local morning review, verify his open task appears once. Reschedule it and confirm history and task ID. Check Alice cannot see it.
4. Run the approved fault drills T04, T08, T09, T15 and T16. Record any skipped drill and reason; a skipped gate is not a pass.
5. Complete the restore drill and review security headers, logs, worker health, backups and alert delivery. Record actual results and unresolved defects.
